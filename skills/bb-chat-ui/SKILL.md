# bb-chat-ui

채팅 표면만 담당한다. 메시지 본문, 메시지 액션, 컴포저다.

기기 판정은 복사한 `lib/use-device.ts`의 `useDeviceChrome()`에서 받은 `device`, `orientation`, `viewport`, `hitTarget`만 쓴다. 복사한 `device.ts`와 `use-device.ts`는 원본 그대로 유지한다. desktop의 글자·버튼 크기는 화면 폭으로 바꾸지 않는다. phone portrait와 landscape는 기존 viewport별 UI를 유지하며, 회전만으로 portrait 배치를 landscape에 적용하지 않는다.

컴포저 초안의 `>` 인용은 호스트 멘션으로 바뀐다. 전문을 저장하는 동안에도 원문 인용은 멘션과 같은 높이와 최대 너비로 제한하고 첫 문단만 보여 준다. 새 멘션에는 첫 화면부터 공통 규격을 적용한다. `diff --git`로 시작하는 코드 인용은 변경 줄 아이콘이고, 파일 이름과 원문에 있는 diff 행 범위를 필에 표시한다. 행 범위가 없으면 파일 이름을 쓴다. 메시지 아래 버튼으로 넣은 인용은 메시지 아이콘이고, 드래그해서 넣은 인용은 인용 아이콘이다. 일반 인용은 첫 줄의 앞부분을 표시한다. 표시용 라벨에서는 굵게·기울임·인라인 코드와 제목·목록·인용 접두 서식을 제거한다. BB가 서식을 먼저 해석해 멘션 노드를 일반 텍스트로 바꾸지 않도록 한다. 보관하는 인용 원문은 유지한다. 전문은 사용자 메시지에 남지 않고, 보낼 때 에이전트에게만 전달된다. 캐럿은 인용 필 안에 머물지 않는다. 백스페이스와 Delete는 인용 필 전체를 지운다.

멘션 필은 작성창, 메시지 편집창, 보낸 메시지, 대기 메시지에서 같은 규격을 쓴다. Agentation, 인용, 파일, 스레드, 스킬을 포함한다. `useDeviceChrome()`의 `device`가 `phone`이고 `viewport`가 `narrow`이면 높이 `32px`, 글자 `14px`와 줄 높이 `18px`, 대표 아이콘 `16px`, 간격 `6px`, 주변 여백 `4px`, 패딩 `6px 14px 6px 12px`, 최대 너비 `240px`다. 그 외에는 높이 `28px`, 글자 `12px`와 줄 높이 `16px`, 대표 아이콘 `14px`, 간격 `4px`, 주변 여백 `3px`, 패딩 `4px 12px 4px 10px`, 최대 너비 `140px`다. 두 환경 모두 부모의 가용 폭 안에 둔다. 짧은 필은 내용만큼 차지하고 긴 필은 한 줄 말줄임이다. 일반 필의 내부 라벨에도 아이콘·패딩·테두리를 뺀 고정 최대 너비를 적용해, 필만 있는 말풍선의 내용 너비 계산에 긴 원문 라벨이 들어가지 않게 한다. 한 줄 컴포저에서도 세로 가운데에 둔다. 코드 변경과 커밋은 일반 최대 너비의 예외로 두고 가용 폭을 쓴다. 커밋은 화면에 해시 앞 7자리만 표시하고 원본 멘션 참조는 유지한다. 작성·편집 중에는 우측 X를 항상 표시하고 그 자리의 패딩을 확보한다. X 모양의 불투명도는 50%다. X는 해당 편집 문서의 멘션 노드를 지우며, 필 본문의 기존 열기 동작과 분리한다. 보낸 메시지의 읽기 상태에는 X가 없다. 새 멘션 추가 때 자동으로 붙은 문단 구분은 공백으로 바꿔 같은 줄에 나란히 놓는다. 기존 초안의 줄바꿈은 유지한다. Add to chat으로 넣은 인용도 필로 바꿀 때 자동 줄바꿈을 정리한다.

컴포저 위 Code Diff는 호스트의 `thread-prompt-banner-git-toggle`과 공개 SDK 환경 상태를 사용한다. 줄 수와 파일 목록은 일반 checkout과 worktree 모두 해당 환경의 `HEAD` 이후 미커밋 변경만 쓴다. 커밋된 코드 라인 수로 대체하지 않는다. 미커밋 변경이 있으면 줄·파일 요약과 보라색 브랜치 아이콘만 표시한다. 미커밋 변경이 없으면 `main`/`master`는 `origin/main`/`origin/master`에 없는 커밋 수를 `↑N`으로 표시한다. 작업 브랜치는 PR 대상 원격 브랜치에 없는 커밋 수를 브랜치명과 함께 표시하고, 미푸시 여부와 숫자는 팝오버에만 둔다. PR 대상은 열린 PR의 base를 우선하고, 없으면 환경의 비교 브랜치 또는 저장소 default branch를 origin의 ref로 사용한다. 개수는 SDK의 `aheadCount`를 사용하며 목록 길이로 세지 않는다. 비교 ref가 실제로 없으면 숫자를 알 수 없음으로 둔다. 조회 중 HEAD가 바뀌거나 일시적으로 조회에 실패하면 불완전한 결과를 표시하지 않고 마지막 정상 결과를 유지한다. 아직 원격 작업 브랜치가 없어도 원격 base가 있으면 PR 후보 수는 계산한다. 원격 비교는 마지막으로 확인한 remote-tracking ref 기준이며 자동 fetch·push는 하지 않는다. 브랜치명은 pill에만 `…` 포함 10자로 제한한다. 팝오버는 main/master를 포함해 보라색 아이콘과 전체 이름을 표시한다. clean main/master의 미푸시 수가 0이면 빈 아이콘 설정과 무관하게 상단 필만 숨기고 전체 정보에서 상세를 유지한다. detached HEAD에는 브랜치 아이콘이나 후보 커밋 수가 없다. 호스트 펼치기는 숨긴다. 정보 줄의 필과 전체 정보 목록은 먼저 팝오버를 연다. 팝오버 타이틀 옆의 `Diff 패널 열기` 아이콘 버튼이 옆 패널의 Diff 탭을 연다. 컴포저의 `Merge base` 비교 기준 선택기는 숨기며 단독 필 판정에서 제외한다.

스레드 목차는 호스트의 `[data-thread-toc]`다. 탭은 숨긴다. 눈금을 클릭하면 그 눈금의 미리보기 메시지로 스크롤한다. 호스트의 메시지 버튼을 실행해 과거 메시지 로딩도 기존 동작을 따른다. 첫 클릭으로 목록이 열리면 목록이 나타난 뒤 한 번 이동한다. 카드는 마우스가 올라간 눈금의 사용자 메시지 하나만 보여 주고, 미리보기는 6줄까지다. 카드 호버는 배경색 없이 살짝 커지며, 그때도 눈금 길이와 선택 색은 유지된다. 카드 면은 컴포저와 같은 glass다. 블러는 `blur(14px) saturate(1.25)`다. 채움은 해당 채팅의 배경에서 계산한다. 일반 채팅은 `--background`, sidebar 톤은 `--sidebar`다. OKLCH의 밝기만 0.075 올리고 채도와 색조는 유지하며, 밝기는 1에서 제한한다. 불투명도는 라이트 68%, 다크 76%다. 순백 배경에서는 밝기를 더 올리지 않고 기존 얇은 그림자로 구분한다. 채팅 배경 자체는 바꾸지 않는다. 실선은 없다. 가장자리는 흐린 inset `0 1px 3px`다. 라이트는 popover 색 35%, 다크는 foreground 색 8%로 부드럽게 이어진다. 메시지를 연 뒤 포인터가 목차 루트 밖으로 나가면 카드는 닫히고, 지금 레일의 눈금 너비와 선택 색은 비워진다. 루트는 남고 레일 버튼만 바뀌어도 지금 눈금을 비운다. 눈금은 오른쪽 끝에 붙고, 가까울수록 왼쪽으로 길어진다. 색이 진한 눈금은 최신 메시지가 아니라 카드에 나온 메시지다.

사이드바 패널 모션은 `sidebar`다. 스레드 목록의 색과 행 표시는 `bb-thread-theme`다.

전송이 끝나면 `selection` 햅틱이 한 번 난다. 그 응답이 끝나면 `success` 햅틱이 한 번 난다. 끝은 보이는 `Working...` 또는 `Thinking…`가 사라질 때다. 프로비저닝과 백그라운드 작업은 세지 않는다. 응답이 시작될 때는 햅틱을 내지 않는다. 중단 버튼(`Stop run`)을 누르면 `selection` 햅틱이 한 번 난다. 맨 밑으로 버튼을 누르면 `impact-light` 햅틱이 한 번 난다. File Diff에서 파일 코드 블럭을 펼치거나 접는 버튼도 `impact-light`가 한 번 난다. 같은 누름의 클릭과 포인터 업은 한 번만 울린다. 모두 모바일 셸의 `haptic` capability가 있을 때만 낸다.

채팅 면, 스레드 헤더, 안전 영역은 호스트 테마를 그대로 따른다. 이 플러그인은 고정 채팅 캔버스를 선언하지 않는다. 페이드 끝은 일반 채팅에서 `--background`, sidebar 톤의 분할 채팅에서 `--sidebar`다. 첨부 메시지의 접힌 글 페이드도 해당 호스트 표면 위에 `--surface-recessed`를 합성한다. 목록이나 sidebar 플러그인의 색 변수와 설정을 읽지 않는다. 컴포저 뒤의 단색 판은 없다. 페이드는 footer 판의 바닥에 붙고 컴포저 위 64px까지 퍼진다. 높이는 컴포저 높이와 아래 여백, 64px의 합이다. 위는 투명하고, 높이의 45%에서 채팅 면 색 12%, 75%에서 35%, 90%에서 65%로 완만하게 이어진다. 마지막 10%에서 배경색 100%에 닿아 하단 경계를 잇는다. 그 위 구간은 반투명을 유지한다. 일반 채팅과 sidebar 톤은 각각 자신의 배경색을 쓴다. 컴포저는 위로 당겨 올리지 않는다. 펼친 후속 메시지 입력 영역의 최소 높이는 모바일·데스크톱 모두 68px다. 상단 배너 높이를 빼는 호스트의 최소 높이 규칙을 덮어써, 필·버튼의 유무로 입력 영역이 32px 늘거나 줄지 않게 한다. 변경 필, 맨 밑으로 버튼, 컴포저, Agentation staging은 같은 glass 표면색을 쓴다. Chat UI가 켜져 있을 때 Agentation의 고정 채움색을 이 규칙으로 덮는다. 서로의 설정이나 색 변수를 읽지 않는다. 블러는 `blur(14px) saturate(1.25)`다. 채움은 해당 채팅의 배경에서 계산한다. 일반 채팅은 `--background`, sidebar 톤은 `--sidebar`다. OKLCH의 밝기만 0.075 올리고 채도와 색조는 유지하며, 밝기는 1에서 제한한다. 불투명도는 라이트 68%, 다크 76%다. 순백 배경에서는 밝기를 더 올리지 않고 기존 얇은 그림자로 구분한다. 채팅 배경 자체는 바꾸지 않는다. 컴포저, 변경 필, 맨 밑으로 버튼, Agentation staging의 실선은 없다. 가장자리는 흐린 inset `0 1px 3px`다. 컴포저의 상단 반사광은 흰색을 라이트 60%, 다크 14%로 섞는다. 변경 필, 맨 밑으로 버튼, Agentation staging은 라이트 popover 색 35%, 다크 foreground 색 8%를 유지한다. 데스크톱 컴포저 그림자는 `0 12px 32px -14px`이고, 커서가 들어가고 나올 때 320ms, `cubic-bezier(0.2, 0.8, 0.2, 1)`로 바뀐다. `useDeviceChrome()`의 `hitTarget`이 `small`일 때 접고 펼치면 모서리가 480ms, `cubic-bezier(0.22, 1, 0.36, 1)`로 바뀐다. 높이는 360ms다. 호스트는 인라인으로 `height 240ms`를 넣고 320ms에 높이를 비운다. 이 플러그인은 그 문자열만 360ms로 바꾸고, 높이가 비면 같은 곡선의 남은 시간으로 이어 간다. `transition`에는 `!important`를 쓰지 않는다. 접히고 펼쳐질 때 컴포저 내용의 아래 가장자리는 바닥에 남고, 위쪽이 줄어든다. 그때 스크롤이 바닥에서 4px 안이면 애니메이션 동안 스크롤을 바닥에 붙인다. 사용자가 위로 스크롤하면 그 붙임은 멈춘다. `viewport`가 `medium` 또는 `wide`이면 접힌 푸터 줄도 아래에 정렬된다. `device`가 `desktop`인 경우 그 애니메이션 동안 scroll anchoring은 꺼 두고, 판이 스크롤 바닥보다 위로 남으면 `translateY`로 되돌린다. `viewport`가 `narrow`이고 컴포저가 접혀 있으면 푸터는 `100dvh`를 넘지 않는다. 위의 배너가 많아도 컴포저는 아래에 남고, 배너 열만 스크롤된다. `prefers-reduced-motion`이면 모서리는 바로 바뀐다. `hitTarget`이 `large`이면 모서리는 바로 바뀐다. `device`가 `phone`이고 `viewport`가 `narrow`인 화면의 컴포저 그림자는 `0 6px 16px -10px`, 포커스는 `0 8px 20px -12px`다. 필과 맨 밑으로 버튼은 `0 6px 18px -12px`다. 컴포저 모서리는 `1.375rem`이고, 접힌 컴포저는 `999px`다. 접힌 컴포저에 핸드오프 줄(`Exit handoff`)이 있으면 모서리는 `1.375rem`다. 컴포저 안 버튼, 전송 껍데기(`[data-promptbox-send-menu]`), Stop의 바깥 모서리는 `999px`다. 이미지를 담은 미리보기 버튼은 빼 둔다. Stop 안의 네모 아이콘은 그대로다.

대기 메시지 큐도 전체 정보에서 여는 한 정보 계열이다. 정보 줄이 큐를 관리하면 기존 숫자 버튼과 native header를 숨기고 새 큐 버튼만 진입점으로 남긴다. 기존 standalone 큐의 위치·높이 CSS와 자동 접기·클릭 처리는 이 큐에 적용하지 않는다. 팝오버는 실제 native 목록과 편집·전송·삭제 동작을 그대로 쓰고, 내부 목록은 제한된 높이에서 스크롤된다. 큐 DOM 노드는 다른 부모로 옮기지 않는다. 정보 줄이 관리하지 않는 standalone 큐에만 다음 레이아웃과 접기 규칙을 적용한다. 접힌 큐는 메시지 개수만 보이는 원형 버튼이다. 호스트의 실제 toggle 버튼을 원형 숫자 영역 전체에 남겨 클릭과 키보드 입력을 받는다. 누르면 메시지 행이 버튼 바로 위에 absolute로 펼쳐지고, 버튼은 아래쪽 화살표로 바뀐다. 행이 접힌 Agentation과 세로로 겹치는 경우에만 Agentation 오른쪽 가장자리에서 8px 뒤부터 폭을 쓴다. 나머지는 전체 폭을 쓴다. 긴 목록은 열린 영역 안에서 스크롤된다. 펼쳐도 큐 슬롯 높이는 32px로 고정한다. 모든 정보 계열의 전체 정보 목록과 각 상세 팝오버는 실제 스크롤할 내용이 남은 방향에만 테마 기반 블러 그라데이션을 표시한다. 처음에는 아래, 중간에는 양쪽, 끝에서는 위에 표시하며, 내용이 짧으면 표시하지 않는다. 대기 메시지처럼 내부 목록이 스크롤되는 경우 그 영역을 따라간다. 힌트는 클릭과 키보드 입력을 막지 않고 해제 시 관찰자와 리스너를 정리한다. 상세는 한 번에 하나만 펼친다. 큐 행 편집 중에는 편집 내용을 잃지 않도록 상세 전환과 닫기를 막는다. 플러그인을 끌 때도 열린 큐 편집기를 강제로 접지 않는다. 정보 줄이 관리하는 큐 상세의 행은 말풍선 없이 본문을 왼쪽, native 액션을 오른쪽에 놓는 간결한 목록이다. 본문은 가용 폭을 쓰고 `12px`, 줄 높이 `1.5`로 표시한다. 행 사이에 얇은 구분선을 두며 본문과 액션 묶음의 배경·그림자는 없앤다. 멘션 필과 편집·전송·삭제 동작은 유지한다. 아래 말풍선 규칙은 standalone 큐에만 적용한다. standalone 큐 행은 사용자 메시지와 같은 오른쪽 말풍선이다. 면은 `surface-recessed`, 테두리는 `border-seam`, 모서리는 `calc(var(--radius) + 4px)`, 글자는 `text-sm` `leading-relaxed`다. `var(--radius-xl)`은 쓰지 않는다. `--radius-xl`은 Tailwind `@theme inline` 안이라 런타임 변수가 아니다. 알약과 말풍선의 불투명도는 1이다. 큐의 일반 텍스트에 적용하는 줄바꿈·글자 크기 규칙에서 멘션 필과 그 자식을 제외해, 필 내부는 공통 한 줄 말줄임 규격을 유지한다. 그 왼쪽에 호스트의 삭제·보내기·편집 버튼이 말풍선과 같은 높이에 있다. 말풍선과 버튼 묶음에는 같은 옅은 그림자를 넣는다. 그림자는 `0 4px 12px -4px`이고 라이트는 잉크색 20%, 다크는 검정 50%다. 그림자가 잘리지 않도록 스크롤 목록 안쪽에 4px 여백을 둔다. 접고 펼치면 목록 높이가 260ms, `cubic-bezier(0.16, 1, 0.3, 1)`로 바뀐다. `prefers-reduced-motion`이면 바로 바뀐다. 처음 보이는 drawer는 호스트 동작으로 한 번 접는다. 이미 접힌 상태로 처음 보인 큐는 사용자의 첫 펼침을 다시 접지 않는다. 메시지가 많아 호스트 caret가 workspace 열기 역할을 할 때는 숨긴 surface handle의 Escape 동작으로 접는다. 인라인 편집이 열려 있으면 초기 자동 접기를 하지 않는다.

보낸 사용자 메시지의 사진과 파일은 말풍선 바로 위에 있다. 사진이 위이고, 파일이 그 다음이고, 그 아래가 글이다. 간격은 `8px`다. 파일 필의 패딩은 `6px 14px 6px 12px`다. `useDeviceChrome()`의 `device`가 `phone`이고 `viewport`가 `narrow`이면 최소 높이 `64px`, 모서리 `20px`, 아이콘 `28px`다. 그 외에는 최소 높이 `40px`, 모서리 `12px`, 아이콘 `18px`다. 말풍선 면은 글자 칸 `.break-words`에 있다. 면은 `surface-recessed`, 테두리는 `border-seam`, 모서리는 `calc(var(--radius) + 4px)`, 패딩은 `0.625rem 1rem`다. 글이 없는 `Sent attachments` 문장은 숨긴다. 긴 글의 `Show more`는 말풍선 아래 패딩 안에 둔다. 첨부가 있는 접힌 메시지의 높이 한도는 `calc(15lh - 8px)`다. 페이드는 글자 칸의 보이는 아래쪽에 겹친다. 페이드의 기준은 실제 잘리는 영역의 하단이다. `Show more` 자리까지 단색 구간을 이어서 마지막 글과 버튼이 겹치지 않게 하고 테두리는 유지한다.

화면을 바꾸는 등록은 `app.tsx`에 둔다. 인용 전문은 `server.ts`가 보관하고, 전송 때 멘션으로 읽는다.


## 컴포저 위 정보

전체 정보 목록에는 현재 데이터가 없는 계열도 `현재 없음`으로 남긴다. 모든 목록 항목은 계열별 아이콘을 표시하며, 현재 정보가 없는 상태에서도 아이콘을 유지한다. 호스트 펼침 화살표 대신 해당 계열 아이콘을 쓰고 Agentation은 원래 glyph를 보존한다. 선택하면 `현재 정보 없음`을 표시하며, 정보가 생기면 실제 상세로 바뀐다. `정보가 없어도 상단 아이콘 표시`(`showEmptyIcons`)는 기본 꺼짐이다. 켜면 `상단 표시`로 선택한 빈 계열도 숫자·가짜 수치 없이 작은 원형 아이콘을 표시한다. 공간이 부족하면 기존 규칙으로 전체 정보 버튼 안에 접힌다. `목록에만 표시`와 `끄기`에는 적용하지 않는다. 토글을 끄면 데이터가 없는 상단 아이콘만 사라지고 실제 정보는 유지한다.

`composer-info` content script가 호스트 카드를 원래 DOM 부모에 둔 채 압축한다. 기본 줄은 Code Diff 필, Child Thread 아바타 스택, 전체 정보 원형 버튼이다. `Settings → Chat UI`에서 각 계열을 `상단 표시`, `목록에만 표시`, `끄기` 중 하나로 설정한다. `끄기`는 상단과 전체 정보 목록 모두에서 제외하며, 전부 끄면 정보 줄도 숨긴다. 실제 컨테이너의 너비를 측정해 한 줄에 안 들어가는 항목은 전체 정보 안에 접는다. Code Diff와 Child Thread를 먼저 배치하며, 넘친 정보와 목록에만 표시하는 정보는 전체 정보에서 열 수 있다. 설정 안내에도 자동 접힘을 설명한다. 스크롤 버튼 자리는 별도로 예약한다. desktop의 버튼·글자 크기는 viewport 폭으로 바꾸지 않는다.

정보 줄의 모든 필·원 버튼·팝오버·상세 버튼은 `glass-surface.ts`의 컴포저 표면 계산을 공유한다. 채팅은 `--background`, sidebar는 `--sidebar`를 기준으로 색조를 유지하고 밝기만 `0.075` 올린다. 투명도는 라이트 `0.68`, 다크 `0.76`이며, `blur(14px) saturate(1.25)`와 주변 버튼의 부드러운 inset 하이라이트를 적용한다. Child Thread는 스택 바탕 없이 각 아바타만 테마 표면에 색상을 섞고, 테두리도 해당 채팅 배경을 따른다. 상세는 한 번에 하나만 펼친다. 같은 필을 다시 누르거나 Escape를 누르면 닫히고, 다른 정보를 누르면 교체된다. 큐 편집 중에는 교체·닫기를 막는다. 설정에서 대기 메시지를 꺼도 편집이 끝날 때까지 열린 상세를 유지한다. 호스트 disclosure와 원래 버튼을 실행해 기존 열기·삭제·승인 동작을 보존한다. 여러 Workflow나 플러그인 안내는 전체 정보에서 각각 선택할 수 있다. Code Diff는 합계와 브랜치뿐 아니라 실제 SDK의 수정 파일·파일별 추가/삭제 줄 수·비교 기준·브랜치 커밋 목록을 팝오버에 표시한다. 파일 목록은 항상 `HEAD` 이후 미커밋 변경 기준이며, 변경 중에는 열린 상세도 갱신한다. PR 후보와 미푸시 커밋 수는 각각의 origin 비교 대상을 명시한다. 줄 수가 없는 파일은 `통계 없음`으로 표시한다. 기준 브랜치 대비 커밋을 미푸시 커밋으로 표시하지 않는다. `Diff 패널 열기`를 눌렀을 때 팝오버를 닫고 옆 Diff 패널을 연다. 상위 스레드·PR·Diff가 한 호스트 카드에 속한 경우 원래 컨텍스트와 액션을 함께 열람한다.

현재 스레드 또는 Child Thread의 입력 요청이 있으면 정보 줄과 나머지 배너, 입력창을 숨기고 요청을 컴포저 바로 위에 둔다. 초안은 수정하거나 지우지 않는다. 요청이 해소되면 정보 줄과 입력창이 복원된다. Archived와 환경이 없는 스레드도 호스트의 상태·복구 액션과 모든 제공 정보를 전체 정보에서 유지한다. 호스트가 생략하는 Plan·Goal·할 일·Child Thread·대기 메시지·PR은 공개 SDK의 읽기 전용 요약으로 보완한다. Diff 요약은 실제 환경 상태를 쓰며, 미푸시 수는 origin의 현재 브랜치 ref와 비교하여 읽는다. 해소되지 않는 ref의 SDK 0은 실제 0으로 표시하지 않는다.

Child Thread는 배경 없는 30px 색상 아바타 스택이다. 마지막 세 스레드를 왼쪽에서 오른쪽으로 겹쳐 보여 주며, 오른쪽 원이 앞에 놓인다. 세 개까지는 별도 숫자가 없고, 더 있으면 스택 맨 오른쪽의 별도 30px 원에 초과 개수 `+N`을 표시한다. 전체 개수는 접근성 라벨과 툴팁에 남긴다. 실행·입력/호스트 대기·종료·오류를 점과 체크로 구분하며, 제목에서 두 글자 이니셜을 만든다. 상세는 공개 SDK 데이터로 아바타·제목·provider·상태 행을 그리고, 각 제목의 실제 스레드 열기 동작을 유지한다. 새 Child Thread 아바타는 bubble처럼 튀어나오고, 실행 중 상태 점은 천천히 호흡한다. 완료 시 짧게 반응한 뒤 정지한다. 정보 변화에는 전체 정보 버튼이 짧게 반응한다. `prefers-reduced-motion`이면 모션을 생략한다. 해제·reload 시 플러그인이 만든 DOM·스타일·속성·관찰자·리스너·예약 작업을 정리한다.

Agentation은 원래 카드의 `data-icon="ChatFeedback"` SVG와 실제 staged 개수만 필에 표시한다. SDK 아이콘 이름으로 다시 그리지 않고 요약·상세 행에서 같은 실제 glyph를 보존한다. 상세는 피드백 본문과 위치·대상 정보를 두 줄로 나누고, 각 행 앞에 같은 아이콘을 둔다. 전체 전송·삭제 버튼은 목록 아래에 둔다. 원래 Agentation DOM과 개별 멘션·전송·삭제, 확인 dialog, 오류 재시도 동작을 유지하며, 상단 X는 원래 접기 동작으로 상세를 닫는다.

정보 줄의 모든 필·아바타 스택·전체 정보 원 버튼과 펼친 목록의 버튼은 사용자 클릭당 `impact-light` 햅틱을 한 번 낸다. 터치·마우스·키보드 활성화를 같은 click 경로에서 처리한다. 호스트 disclosure에 전달하는 합성 클릭과 pointerup은 추가 진동을 만들지 않는다. 빠르게 다른 정보를 선택해도 각 클릭을 처리하며, disabled 버튼과 `haptic` capability가 없는 셸에서는 울리지 않는다.

기존 boolean 설정을 쓴 설치를 업그레이드할 때는 빌드·reload 전에 `bb plugin config bb-chat-ui --json`의 값을 보관하고, reload 후 같은 키에 `true → 상단 표시`, `false → 목록에만 표시`로 저장해 선택을 유지한다.

Code Diff pill의 커밋 수는 `commits` 문구 대신 가운데 원과 가로선이 있는 커밋 아이콘과 숫자로 압축한다. 접근성 라벨과 툴팁에는 커밋 개수 의미를 유지한다. 팝오버에 HEAD 이후 변경 파일이 있으면 항상 커밋 제목과 목록보다 위에 둔다. 열린 팝오버를 갱신해도 같은 순서를 유지한다. 커밋 행 왼쪽의 원을 세로선으로 연결하고 첫·마지막 원 밖으로는 선을 늘리지 않는다. 파일 행 왼쪽에는 BB 스레드 정보의 실제 glyph와 같은 아이콘을 둔다. 수정은 `DiffModified`, 추가와 미추적(`??`)은 `DiffAdded`, 삭제는 `DiffRemoved`, 이름 변경은 `DiffRenamed`, 복사는 `Copy`, 충돌은 `DiffConflict`, 상태 불명(`?`)은 `CircleQuestion`이다. 추가·미추적은 `text-diff-added`, 삭제는 `text-diff-removed`, 충돌은 `text-destructive`, 나머지는 `text-subtle-foreground`를 사용한다. 파일 경로와 라인 통계, 기존 아이콘 크기와 행 배치는 유지한다. 팝오버의 일반 안내 문구는 표시하지 않으며, PR 후보의 미푸시 보조 줄은 개수를 확인할 수 있을 때만 표시한다.

Diff 재조회는 마지막 정상 표시를 유지한 채 진행한다. 메시지 스트림·제목 등 환경과 무관한 스레드 변경으로 데이터를 비우거나 재조회하지 않는다. 환경 변경과 5초 polling·focus에서 완성된 결과로 교체하며, 조회 중 변경 이벤트가 오면 이전 요청 결과를 버린다. 다른 스레드로 이동하면 이전 스레드 데이터를 표시하지 않고, 환경 해제는 확인된 뒤 비운다.

컴포저 정보 팝오버의 스크롤은 채팅으로 전달하지 않는다. 내부 목록·편집기의 기본 wheel·한 손가락 스크롤은 유지하고, 팝오버가 짧거나 위·아래 끝인 경우 바깥 스크롤로 이어지지 않게 한다. 팝오버 밖의 채팅 스크롤과 pinch zoom은 유지하며 해제 시 관련 리스너를 정리한다.

스레드 첫 진입에서 Diff SDK source가 아직 비어 있으면 상단 Diff 필을 표시하지 않는다. 최초 결과의 작업트리·브랜치·미푸시 상태로 바로 표시하며, 빈 아이콘 설정도 이 로딩 상태에는 적용하지 않는다. 전체 정보 목록은 유지한다.

Diff 팝오버의 커밋 목록은 SDK `authoredAt` 기준 최신순으로 표시한다. 동일 시각은 원래 상대 순서를 유지하며, 팝오버를 연 상태에서 목록이 갱신되어도 같은 정렬을 적용한다.

정보 줄에서 여는 대기 메시지 큐는 최대 높이를 `min(36dvh,16rem)`으로 제한한다. 짧은 목록은 내용만큼 줄어들고, 긴 목록은 호스트의 내부 메시지 목록에서만 스크롤한다. 팝오버와 애니메이션 frame에는 별도 스크롤을 만들지 않는다. 기존 행의 편집·전송·삭제와 편집 중 초안 보호, 남은 스크롤 방향의 블러 힌트를 유지한다.

대기 메시지 큐 pill은 SDK의 계열별 `Clock` 아이콘을 우선 사용한다. 호스트 disclosure의 숨겨진 화살표를 복제해 큐 아이콘을 없애지 않는다.

상단 정보 pill은 처음 실제로 표시될 때 Child Thread 아바타와 같은 460ms 버블 모션을 한 번 재생한다. 입력 요청이나 너비 부족으로 숨겨진 pill은 처음 보일 때까지 기다린다. 데이터 갱신·설정 재활성화·크기 변경으로 이미 표시했던 계열의 모션을 반복하지 않는다. Child Thread 스택은 기존 개별 아바타 모션만 유지한다. 너비 계산은 모션의 scale과 무관한 레이아웃 너비를 사용하며, `prefers-reduced-motion`이면 모션을 생략하고 해제 시 진행 중인 모션을 취소한다.

팝오버의 사이드 패널·플러그인 페이지 열기는 타이틀 바로 옆의 작은 외부 열기 아이콘으로 표시한다. 기존 목적지와 동작을 유지하고 툴팁·접근성 라벨로 목적지를 구분한다. 해당 액션이 있을 때만 아이콘을 제공한다. 호스트 버튼·링크는 원래 부모에 남긴 채 숨기고 아이콘 클릭을 원래 액션에 전달한다. disabled 상태와 DOM 갱신을 반영하며 해제 시 원래 표시를 복원한다. 전송·삭제 등 다른 액션은 압축하지 않는다.

정보 줄이 관리하는 대기 큐에서는 목록 하단의 native `Collapse queued messages` 핸들도 숨긴다. 원래 DOM과 동작은 유지하며 pill 재클릭과 Escape로 닫는다. standalone 큐의 핸들은 유지한다.

Diff 팝오버의 미커밋 요약은 `HEAD · +N −N · N files`로 표시한다. 전체 비교 의미는 툴팁과 접근성 라벨에 유지한다. 커밋 제목은 `origin/<base> → HEAD · 커밋 아이콘 N`으로 줄이고, PR 후보·미푸시 구분은 툴팁과 접근성 라벨에 유지한다. 개수를 확인하지 못하면 `—`로 표시하며 목록 길이로 대체하지 않는다. `HEAD~`는 이전 커밋을 뜻하므로 작업트리 기준 표기로 쓰지 않는다.

버블 모션은 110%까지 한 번 커졌다가 100%로 돌아온다. 첫 등장은 `scale(.85)`와 8px 아래에서 시작해 60% 시점에 `scale(1.1)`과 2px 위에 도달하고, 460ms에 제자리로 돌아온다. 중간의 반복 반동은 없다. CSS 아바타와 Web Animations 필은 각 구간에 `cubic-bezier(.36,0,.18,1)`을 적용해 방향을 바꾸는 지점에서도 부드럽게 감속한다. 전체 정보 상태 변화와 Child Thread 완료의 반응은 360ms에 100% → 110% → 100%다. 같은 갱신에서 처음 보이는 pill과 Child Thread 아바타는 왼쪽부터 45ms씩 간격을 두고 시작한다. 지연 중에도 첫 자세를 유지하며 숨겨진 pill은 순서에 포함하지 않는다.

대기 메시지 개수는 native header의 `data-queued-messages-count` 안 현재 숫자만 읽는다. 이 속성이 없는 기존 숫자 구조도 지원하며, 읽기용 복사본에서 `aria-hidden`, 이전 숫자 속성, `bb-count-roll-out` 노드를 제외하고 숫자만 검증한다. 실제 여러 자리 개수는 잘라내지 않는다. 롤아웃 중인 이전 숫자와 대기 시간 표시는 제외한다. 개수 변경도 정보 줄의 갱신 기준에 포함해 추가·전송·삭제 직후 pill 숫자와 접근성 라벨을 함께 갱신한다.
