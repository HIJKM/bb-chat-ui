# bb-chat-ui

채팅 표면만 담당한다. 메시지 본문, 메시지 액션, 컴포저다.

기기 판정은 복사한 `lib/use-device.ts`의 `useDeviceChrome()`에서 받은 `device`, `orientation`, `viewport`, `hitTarget`만 쓴다. 복사한 `device.ts`와 `use-device.ts`는 원본 그대로 유지한다. desktop의 글자·버튼 크기는 화면 폭으로 바꾸지 않는다. phone portrait와 landscape는 기존 viewport별 UI를 유지하며, 회전만으로 portrait 배치를 landscape에 적용하지 않는다.

컴포저 초안의 `>` 인용은 호스트 멘션으로 바뀐다. 전문을 저장하는 동안에도 원문 인용은 멘션과 같은 높이와 최대 너비로 제한하고 첫 문단만 보여 준다. 새 멘션에는 첫 화면부터 공통 규격을 적용한다. `diff --git`로 시작하는 코드 인용은 변경 줄 아이콘이고, 파일 이름과 원문에 있는 diff 행 범위를 필에 표시한다. 행 범위가 없으면 파일 이름을 쓴다. 메시지 아래 버튼으로 넣은 인용은 메시지 아이콘이고, 드래그해서 넣은 인용은 인용 아이콘이다. 일반 인용은 첫 줄의 앞부분을 표시한다. 표시용 라벨에서는 굵게·기울임·인라인 코드와 제목·목록·인용 접두 서식을 제거한다. BB가 서식을 먼저 해석해 멘션 노드를 일반 텍스트로 바꾸지 않도록 한다. 보관하는 인용 원문은 유지한다. 전문은 사용자 메시지에 남지 않고, 보낼 때 에이전트에게만 전달된다. 캐럿은 인용 필 안에 머물지 않는다. 백스페이스와 Delete는 인용 필 전체를 지운다.

멘션 필은 작성창, 메시지 편집창, 보낸 메시지, 대기 메시지에서 같은 규격을 쓴다. Agentation, 인용, 파일, 스레드, 스킬을 포함한다. `useDeviceChrome()`의 `device`가 `phone`이고 `viewport`가 `narrow`이면 높이 `32px`, 글자 `14px`와 줄 높이 `18px`, 대표 아이콘 `16px`, 간격 `6px`, 주변 여백 `4px`, 패딩 `6px 14px 6px 12px`, 최대 너비 `240px`다. 그 외에는 높이 `28px`, 글자 `12px`와 줄 높이 `16px`, 대표 아이콘 `14px`, 간격 `4px`, 주변 여백 `3px`, 패딩 `4px 12px 4px 10px`, 최대 너비 `140px`다. 두 환경 모두 부모의 가용 폭 안에 둔다. 짧은 필은 내용만큼 차지하고 긴 필은 한 줄 말줄임이다. 일반 필의 내부 라벨에도 아이콘·패딩·테두리를 뺀 고정 최대 너비를 적용해, 필만 있는 말풍선의 내용 너비 계산에 긴 원문 라벨이 들어가지 않게 한다. 한 줄 컴포저에서도 세로 가운데에 둔다. 코드 변경과 커밋은 일반 최대 너비의 예외로 두고 가용 폭을 쓴다. 커밋은 화면에 해시 앞 7자리만 표시하고 원본 멘션 참조는 유지한다. 작성·편집 중에는 우측 X를 항상 표시하고 그 자리의 패딩을 확보한다. X 모양의 불투명도는 50%다. X는 해당 편집 문서의 멘션 노드를 지우며, 필 본문의 기존 열기 동작과 분리한다. 보낸 메시지의 읽기 상태에는 X가 없다. 새 멘션 추가 때 자동으로 붙은 문단 구분은 공백으로 바꿔 같은 줄에 나란히 놓는다. 기존 초안의 줄바꿈은 유지한다. Add to chat으로 넣은 인용도 필로 바꿀 때 자동 줄바꿈을 정리한다.

컴포저 위 변경 요약은 호스트의 `thread-prompt-banner-git-toggle`이다. 이 플러그인은 그 버튼을 필로 바꾼다. 내용은 아이콘, 줄 수, `·`, 파일 수다. 줄 수와 파일 수는 해당 스레드 환경의 `HEAD` 대비 미커밋 변경을 쓴다. 이미 커밋한 브랜치 변경은 그 수에 합산하지 않는다. 워크트리이고 미커밋 변경이 없으면, 그 워크트리의 머지 베이스 대비 커밋된 변경을 줄 수와 파일 수로 표시한다. 일반 체크아웃의 커밋된 브랜치 변경은 그렇게 채우지 않는다. 현재 브랜치가 저장소의 기본 브랜치와 다르면 필 맨 오른쪽에 보라색 브랜치 아이콘을 하나 표시하고, 툴팁에 브랜치 이름을 넣는다. detached HEAD에는 브랜치 아이콘이 없다. 호스트 펼치기는 숨긴다. 정보 줄의 Code Diff 필과 전체 정보 목록은 먼저 변경 요약 팝오버를 연다. 팝오버의 `Diff 패널 열기` 버튼이 옆 패널의 Diff 탭을 연다. 컴포저의 `Merge base` 비교 기준 선택기는 숨긴다. 숨긴 선택기는 단독 필 판정에서 제외한다.

스레드 목차는 호스트의 `[data-thread-toc]`다. 탭은 숨긴다. 눈금을 클릭하면 그 눈금의 미리보기 메시지로 스크롤한다. 호스트의 메시지 버튼을 실행해 과거 메시지 로딩도 기존 동작을 따른다. 첫 클릭으로 목록이 열리면 목록이 나타난 뒤 한 번 이동한다. 카드는 마우스가 올라간 눈금의 사용자 메시지 하나만 보여 주고, 미리보기는 6줄까지다. 카드 호버는 배경색 없이 살짝 커지며, 그때도 눈금 길이와 선택 색은 유지된다. 카드 면은 컴포저와 같은 glass다. 블러는 `blur(14px) saturate(1.25)`다. 채움은 해당 채팅의 배경에서 계산한다. 일반 채팅은 `--background`, sidebar 톤은 `--sidebar`다. OKLCH의 밝기만 0.075 올리고 채도와 색조는 유지하며, 밝기는 1에서 제한한다. 불투명도는 라이트 68%, 다크 76%다. 순백 배경에서는 밝기를 더 올리지 않고 기존 얇은 그림자로 구분한다. 채팅 배경 자체는 바꾸지 않는다. 실선은 없다. 가장자리는 흐린 inset `0 1px 3px`다. 라이트는 popover 색 35%, 다크는 foreground 색 8%로 부드럽게 이어진다. 메시지를 연 뒤 포인터가 목차 루트 밖으로 나가면 카드는 닫히고, 지금 레일의 눈금 너비와 선택 색은 비워진다. 루트는 남고 레일 버튼만 바뀌어도 지금 눈금을 비운다. 눈금은 오른쪽 끝에 붙고, 가까울수록 왼쪽으로 길어진다. 색이 진한 눈금은 최신 메시지가 아니라 카드에 나온 메시지다.

사이드바 패널 모션은 `sidebar`다. 스레드 목록의 색과 행 표시는 `bb-thread-theme`다.

전송이 끝나면 `selection` 햅틱이 한 번 난다. 그 응답이 끝나면 `success` 햅틱이 한 번 난다. 끝은 보이는 `Working...` 또는 `Thinking…`가 사라질 때다. 프로비저닝과 백그라운드 작업은 세지 않는다. 응답이 시작될 때는 햅틱을 내지 않는다. 중단 버튼(`Stop run`)을 누르면 `selection` 햅틱이 한 번 난다. 맨 밑으로 버튼을 누르면 `impact-light` 햅틱이 한 번 난다. File Diff에서 파일 코드 블럭을 펼치거나 접는 버튼도 `impact-light`가 한 번 난다. 같은 누름의 클릭과 포인터 업은 한 번만 울린다. 모두 모바일 셸의 `haptic` capability가 있을 때만 낸다.

채팅 면, 스레드 헤더, 안전 영역은 호스트 테마를 그대로 따른다. 이 플러그인은 고정 채팅 캔버스를 선언하지 않는다. 페이드 끝은 일반 채팅에서 `--background`, sidebar 톤의 분할 채팅에서 `--sidebar`다. 첨부 메시지의 접힌 글 페이드도 해당 호스트 표면 위에 `--surface-recessed`를 합성한다. 목록이나 sidebar 플러그인의 색 변수와 설정을 읽지 않는다. 컴포저 뒤의 단색 판은 없다. 페이드는 footer 판의 바닥에 붙고 컴포저 위 64px까지 퍼진다. 높이는 컴포저 높이와 아래 여백, 64px의 합이다. 위는 투명하고, 높이의 45%에서 채팅 면 색 12%, 75%에서 35%, 90%에서 65%로 완만하게 이어진다. 마지막 10%에서 배경색 100%에 닿아 하단 경계를 잇는다. 그 위 구간은 반투명을 유지한다. 일반 채팅과 sidebar 톤은 각각 자신의 배경색을 쓴다. 컴포저는 위로 당겨 올리지 않는다. 펼친 후속 메시지 입력 영역의 최소 높이는 모바일·데스크톱 모두 68px다. 상단 배너 높이를 빼는 호스트의 최소 높이 규칙을 덮어써, 필·버튼의 유무로 입력 영역이 32px 늘거나 줄지 않게 한다. 변경 필, 맨 밑으로 버튼, 컴포저, Agentation staging은 같은 glass 표면색을 쓴다. Chat UI가 켜져 있을 때 Agentation의 고정 채움색을 이 규칙으로 덮는다. 서로의 설정이나 색 변수를 읽지 않는다. 블러는 `blur(14px) saturate(1.25)`다. 채움은 해당 채팅의 배경에서 계산한다. 일반 채팅은 `--background`, sidebar 톤은 `--sidebar`다. OKLCH의 밝기만 0.075 올리고 채도와 색조는 유지하며, 밝기는 1에서 제한한다. 불투명도는 라이트 68%, 다크 76%다. 순백 배경에서는 밝기를 더 올리지 않고 기존 얇은 그림자로 구분한다. 채팅 배경 자체는 바꾸지 않는다. 컴포저, 변경 필, 맨 밑으로 버튼, Agentation staging의 실선은 없다. 가장자리는 흐린 inset `0 1px 3px`다. 컴포저의 상단 반사광은 흰색을 라이트 60%, 다크 14%로 섞는다. 변경 필, 맨 밑으로 버튼, Agentation staging은 라이트 popover 색 35%, 다크 foreground 색 8%를 유지한다. 데스크톱 컴포저 그림자는 `0 12px 32px -14px`이고, 커서가 들어가고 나올 때 320ms, `cubic-bezier(0.2, 0.8, 0.2, 1)`로 바뀐다. `useDeviceChrome()`의 `hitTarget`이 `small`일 때 접고 펼치면 모서리가 480ms, `cubic-bezier(0.22, 1, 0.36, 1)`로 바뀐다. 높이는 360ms다. 호스트는 인라인으로 `height 240ms`를 넣고 320ms에 높이를 비운다. 이 플러그인은 그 문자열만 360ms로 바꾸고, 높이가 비면 같은 곡선의 남은 시간으로 이어 간다. `transition`에는 `!important`를 쓰지 않는다. 접히고 펼쳐질 때 컴포저 내용의 아래 가장자리는 바닥에 남고, 위쪽이 줄어든다. 그때 스크롤이 바닥에서 4px 안이면 애니메이션 동안 스크롤을 바닥에 붙인다. 사용자가 위로 스크롤하면 그 붙임은 멈춘다. `viewport`가 `medium` 또는 `wide`이면 접힌 푸터 줄도 아래에 정렬된다. `device`가 `desktop`인 경우 그 애니메이션 동안 scroll anchoring은 꺼 두고, 판이 스크롤 바닥보다 위로 남으면 `translateY`로 되돌린다. `viewport`가 `narrow`이고 컴포저가 접혀 있으면 푸터는 `100dvh`를 넘지 않는다. 위의 배너가 많아도 컴포저는 아래에 남고, 배너 열만 스크롤된다. `prefers-reduced-motion`이면 모서리는 바로 바뀐다. `hitTarget`이 `large`이면 모서리는 바로 바뀐다. `device`가 `phone`이고 `viewport`가 `narrow`인 화면의 컴포저 그림자는 `0 6px 16px -10px`, 포커스는 `0 8px 20px -12px`다. 필과 맨 밑으로 버튼은 `0 6px 18px -12px`다. 컴포저 모서리는 `1.375rem`이고, 접힌 컴포저는 `999px`다. 접힌 컴포저에 핸드오프 줄(`Exit handoff`)이 있으면 모서리는 `1.375rem`다. 컴포저 안 버튼, 전송 껍데기(`[data-promptbox-send-menu]`), Stop의 바깥 모서리는 `999px`다. 이미지를 담은 미리보기 버튼은 빼 둔다. Stop 안의 네모 아이콘은 그대로다.

대기 메시지 큐도 전체 정보에서 여는 한 정보 계열이다. 큐 DOM 노드는 다른 부모로 옮기지 않는다. 접힌 큐는 메시지 개수만 보이는 원형 버튼이다. 호스트의 실제 toggle 버튼을 원형 숫자 영역 전체에 남겨 클릭과 키보드 입력을 받는다. 누르면 메시지 행이 버튼 바로 위에 absolute로 펼쳐지고, 버튼은 아래쪽 화살표로 바뀐다. 행이 접힌 Agentation과 세로로 겹치는 경우에만 Agentation 오른쪽 가장자리에서 8px 뒤부터 폭을 쓴다. 나머지는 전체 폭을 쓴다. 긴 목록은 열린 영역 안에서 스크롤된다. 펼쳐도 큐 슬롯 높이는 32px로 고정한다. 모든 정보 계열의 상세는 한 번에 하나만 펼친다. 큐 행 편집 중에는 편집 내용을 잃지 않도록 상세 전환과 닫기를 막는다. 플러그인을 끌 때도 열린 큐 편집기를 강제로 접지 않는다. 큐 상세 안의 행은 사용자 메시지와 같은 오른쪽 말풍선이다. 면은 `surface-recessed`, 테두리는 `border-seam`, 모서리는 `calc(var(--radius) + 4px)`, 글자는 `text-sm` `leading-relaxed`다. `var(--radius-xl)`은 쓰지 않는다. `--radius-xl`은 Tailwind `@theme inline` 안이라 런타임 변수가 아니다. 알약과 말풍선의 불투명도는 1이다. 큐의 일반 텍스트에 적용하는 줄바꿈·글자 크기 규칙에서 멘션 필과 그 자식을 제외해, 필 내부는 공통 한 줄 말줄임 규격을 유지한다. 그 왼쪽에 호스트의 삭제·보내기·편집 버튼이 말풍선과 같은 높이에 있다. 말풍선과 버튼 묶음에는 같은 옅은 그림자를 넣는다. 그림자는 `0 4px 12px -4px`이고 라이트는 잉크색 20%, 다크는 검정 50%다. 그림자가 잘리지 않도록 스크롤 목록 안쪽에 4px 여백을 둔다. 접고 펼치면 목록 높이가 260ms, `cubic-bezier(0.16, 1, 0.3, 1)`로 바뀐다. `prefers-reduced-motion`이면 바로 바뀐다. 처음 보이는 drawer는 호스트 동작으로 한 번 접는다. 이미 접힌 상태로 처음 보인 큐는 사용자의 첫 펼침을 다시 접지 않는다. 메시지가 많아 호스트 caret가 workspace 열기 역할을 할 때는 숨긴 surface handle의 Escape 동작으로 접는다. 인라인 편집이 열려 있으면 초기 자동 접기를 하지 않는다.

보낸 사용자 메시지의 사진과 파일은 말풍선 바로 위에 있다. 사진이 위이고, 파일이 그 다음이고, 그 아래가 글이다. 간격은 `8px`다. 파일 필의 패딩은 `6px 14px 6px 12px`다. `useDeviceChrome()`의 `device`가 `phone`이고 `viewport`가 `narrow`이면 최소 높이 `64px`, 모서리 `20px`, 아이콘 `28px`다. 그 외에는 최소 높이 `40px`, 모서리 `12px`, 아이콘 `18px`다. 말풍선 면은 글자 칸 `.break-words`에 있다. 면은 `surface-recessed`, 테두리는 `border-seam`, 모서리는 `calc(var(--radius) + 4px)`, 패딩은 `0.625rem 1rem`다. 글이 없는 `Sent attachments` 문장은 숨긴다. 긴 글의 `Show more`는 말풍선 아래 패딩 안에 둔다. 첨부가 있는 접힌 메시지의 높이 한도는 `calc(15lh - 8px)`다. 페이드는 글자 칸의 보이는 아래쪽에 겹친다. 페이드의 기준은 실제 잘리는 영역의 하단이다. `Show more` 자리까지 단색 구간을 이어서 마지막 글과 버튼이 겹치지 않게 하고 테두리는 유지한다.

화면을 바꾸는 등록은 `app.tsx`에 둔다. 인용 전문은 `server.ts`가 보관하고, 전송 때 멘션으로 읽는다.


## 컴포저 위 정보

전체 정보 목록에는 현재 데이터가 없는 계열도 `현재 없음`으로 남긴다. 선택하면 `현재 정보 없음`을 표시하며, 정보가 생기면 실제 상세로 바뀐다. 데이터가 없는 상단 필이나 가상의 Diff 수치는 만들지 않는다.

`composer-info` content script가 호스트 카드를 원래 DOM 부모에 둔 채 압축한다. 기본 줄은 Code Diff 필, Child Thread 아바타 스택, 전체 정보 원형 버튼이다. `Settings → Chat UI`에서 각 계열을 `상단 표시`, `목록에만 표시`, `끄기` 중 하나로 설정한다. `끄기`는 상단과 전체 정보 목록 모두에서 제외하며, 전부 끄면 정보 줄도 숨긴다. 실제 컨테이너의 너비를 측정해 한 줄에 안 들어가는 항목은 전체 정보 안에 접는다. Code Diff와 Child Thread를 먼저 배치하며, 넘친 정보와 목록에만 표시하는 정보는 전체 정보에서 열 수 있다. 설정 안내에도 자동 접힘을 설명한다. 스크롤 버튼 자리는 별도로 예약한다. desktop의 버튼·글자 크기는 viewport 폭으로 바꾸지 않는다.

상세는 단색 `--surface-raised-solid` 위에서 한 번에 하나만 펼친다. 같은 필을 다시 누르거나 Escape를 누르면 닫히고, 다른 정보를 누르면 교체된다. 큐 편집 중에는 교체·닫기를 막는다. 설정에서 대기 메시지를 꺼도 편집이 끝날 때까지 열린 상세를 유지한다. 호스트 disclosure와 원래 버튼을 실행해 기존 열기·삭제·승인 동작을 보존한다. 여러 Workflow나 플러그인 안내는 전체 정보에서 각각 선택할 수 있다. Code Diff는 먼저 줄 수·파일 수·제공되는 브랜치를 팝오버에 표시한다. `Diff 패널 열기`를 눌렀을 때 팝오버를 닫고 옆 Diff 패널을 연다. 상위 스레드·PR·Diff가 한 호스트 카드에 속한 경우 원래 컨텍스트와 액션을 함께 열람한다.

현재 스레드 또는 Child Thread의 입력 요청이 있으면 정보 줄과 나머지 배너, 입력창을 숨기고 요청을 컴포저 바로 위에 둔다. 초안은 수정하거나 지우지 않는다. 요청이 해소되면 정보 줄과 입력창이 복원된다. Archived와 환경이 없는 스레드도 호스트의 상태·복구 액션과 모든 제공 정보를 전체 정보에서 유지한다. 호스트가 생략하는 Plan·Goal·할 일·Child Thread·대기 메시지·PR은 공개 SDK의 읽기 전용 요약으로 보완한다. Diff 요약은 실제 환경 상태를 쓰며, 제공되지 않는 미푸시 커밋 수를 만들어 표시하지 않는다.

새 Child Thread 아바타는 bubble처럼 튀어나오고, 실행 중 상태 점은 천천히 호흡한다. 완료 시 짧게 반응한 뒤 정지한다. 정보 변화에는 전체 정보 버튼이 짧게 반응한다. `prefers-reduced-motion`이면 모션을 생략한다. 해제·reload 시 플러그인이 만든 DOM·스타일·속성·관찰자·리스너·예약 작업을 정리한다.

기존 boolean 설정을 쓴 설치를 업그레이드할 때는 빌드·reload 전에 `bb plugin config bb-chat-ui --json`의 값을 보관하고, reload 후 같은 키에 `true → 상단 표시`, `false → 목록에만 표시`로 저장해 선택을 유지한다.
